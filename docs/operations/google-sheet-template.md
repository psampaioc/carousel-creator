# Google Sheet research queue

The native Google Sheet is the traceable handoff between the daily research worker and the private app. The `Candidates` tab must keep these headers in row 1, in this order:

`research_run_id`, `external_row_id`, `title`, `format`, `start_at`, `end_at`, `venue`, `city`, `topic_relevance`, `week_match`, `geography_band`, `sources_json`, `supported_facts_json`, `conflicts_json`, `images_json`, `editorial_status`, `updated_at`.

## Controlled values

- `format`: `in_person`, `online`, or `hybrid`.
- `topic_relevance`: an evidence-informed integer from 0 to 100. This is the first ranking input.
- `week_match`: `true` only when the event occurs during the selected Monday-Sunday calendar week.
- `geography_band`: `coimbra`, `north`, `central`, or `online`.
- `editorial_status`: the worker may write only `imported` or `needs_attention`. Approval remains an operator action in the app.
- Dates use ISO 8601 with an explicit timezone; use Portugal local time for physical events.

## Repeatable evidence fields

The four `_json` cells contain JSON arrays so one row can preserve any number of sources, claims, conflicts, and image candidates without widening the sheet.

- `sources_json`: `{sourceId, url, label, excerpt, collectedAt, isOfficial}`. Every source needs a unique `sourceId`, HTTP(S) URL, a concise captured fact note, and collection time.
- `supported_facts_json`: `{field, value, sourceIds}`. `field` is one of `title`, `startAt`, `endAt`, `venue`, `city`, or `status`; every source ID must exist in `sources_json`.
- `conflicts_json`: `{field, values}`. Record every materially different value. Do not choose a winner.
- `images_json`: `{driveFileId, sourceUrl, provenance, collectedAt}`. `provenance` is `official`, `announcement`, or `generated`. Preserve priority order in the array.

The app treats absent evidence, malformed JSON, inaccessible Drive files, unsupported dates, and conflicts as visible import findings. Such rows enter `needs_attention`; they never become ready for review.

## Stable identity and updates

`external_row_id` is a durable event-row identity generated by the research worker, not a sheet row number. Reusing it updates the existing Convex candidate and replaces its imported evidence snapshot. A corrected row keeps the same ID; a genuinely different event gets a new ID.

The `Run log` tab records `run_id`, `started_at`, `finished_at`, `added`, `updated`, `rejected`, `conflicts`, and `notes` for each daily pass.
